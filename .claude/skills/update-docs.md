# Скилл: Обновление документации проекта

Этот скилл обновляет всю проектную документацию на основе текущего состояния кода, git-истории и завершённых задач.

## Язык

ВСЯ документация пишется ТОЛЬКО НА РУССКОМ ЯЗЫКЕ. Исключение — CLAUDE.md (технический файл для Claude Code, на английском).

## Файлы для обновления

### 1. README.md

- Таблица возможностей (добавить новые фичи, обновить статусы)
- Счётчик компонентов в секции «Архитектура» (посчитать: `find src/components -name "*.tsx" | wc -l`)
- Дорожная карта (gantt-диаграмма — отметить завершённые спринты)

### 2. CHANGELOG.md (Журнал изменений)

- Добавить записи в секцию `[Unreleased]` для текущего спринта
- Формат: `### ✨ Спринт NNN — Название`
- Подсекции: `#### Добавлено`, `#### Изменено`, `#### Исправлено`
- Анализировать git log с последнего релиза: `git log --oneline $(git describe --tags --abbrev=0 2>/dev/null || echo HEAD~50)..HEAD`

### 3. PROJECT_STATUS.md (Статус проекта)

- Бейдж спринта и прогресса в шапке
- Таблица текущего спринта (задачи + прогресс-бейджи)
- Таблица следующего спринта
- Ключевые метрики (компоненты, хуки, бандл, покрытие)
- Секция «Последние достижения»

### 4. SPRINTS/SPRINT-PROGRESS.md

- Таблица «Общий статус» — обновить диапазон завершённых спринтов
- Добавить/обновить секцию текущего спринта с чекбоксами задач
- Дата «Последнее обновление»

### 5. CLAUDE.md (только метаданные, на английском)

- `Current Status` — номер спринта, статус, счётчик компонентов
- `Last Updated` — дата и название спринта

## Как собирать данные

```bash
# Счётчик компонентов
find src/components -name "*.tsx" | wc -l

# Счётчик хуков
find src/hooks -name "*.ts" -o -name "*.tsx" | wc -l

# Номер текущего спринта — из PROJECT_STATUS.md или SPRINTS/
grep -oP 'sprint-\K\d+' PROJECT_STATUS.md | head -1

# Последние коммиты для changelog
git log --oneline -30

# Размер бандла (если доступен)
grep -r "size" .size-limit.json 2>/dev/null || echo "950 KB бюджет"
```

## Правила

- Не дублировать информацию — каждый файл отвечает за свою зону
- Сохранять существующую структуру и форматирование файлов
- Бейджи shields.io — использовать существующий стиль (`for-the-badge` в шапках, `flat-square` в таблицах)
- При отсутствии изменений в файле — не трогать его
- Коммитить все изменения одним коммитом и пушить на текущую ветку
