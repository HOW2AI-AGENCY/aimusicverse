## 1. Обзор продукта (для владельца)

**MusicVerse AI** — платформа создания музыки с помощью ИИ, работающая как **нативное Telegram Mini App** (мини-приложение внутри Telegram, а не отдельный сайт с входом через Telegram). Пользователь генерирует, редактирует, микширует треки и делится ими, не покидая мессенджер.

### Что умеет продукт

| Возможность             | Описание                                                                 |
| ----------------------- | ------------------------------------------------------------------------ |
| 🎵 Генерация музыки     | Текст/стиль → готовый трек через **Suno AI v5**, всегда 2 версии (A/B)   |
| 🎤 Клонирование голоса  | Пользователь загружает образец голоса и поёт им                          |
| 📝 AI-ассистент текстов | Помощь в написании и доработке лирики                                    |
| 🎛 MIDI-транскрипция     | Аудио → ноты/MIDI через **Klang.io** (6 моделей)                         |
| 🔀 Разделение на стемы  | Извлечение вокала / барабанов / баса из трека                            |
| 🏗 Студия                | Мультитрек-редактор, микшер, инструменты                                 |
| 👥 Сообщество           | Лента, профили артистов, лайки, комментарии, плейлисты                   |
| 💎 Монетизация          | Подписки и покупка кредитов: **Telegram Stars** + **Tinkoff** (карты РФ) |
| 🔔 Уведомления          | In-app и push при завершении генерации                                   |
| 🌐 Языки                | Русский и английский (переключение в интерфейсе)                         |

### Как это работает (упрощённо)

```
Пользователь в Telegram
        │  открывает мини-приложение @AIMusicVerseBot
        ▼
Mini App (интерфейс)  ──►  Lovable Cloud / Supabase (база, авторизация, файлы)
        │                          │
        │                          ├──►  Suno AI      (генерация музыки)     ← платный API
        │                          ├──►  Klang.io     (MIDI)                 ← платный API
        │                          ├──►  Lovable AI    (тексты, анализ)      ← платный API
        │                          └──►  Telegram Bot  (уведомления, оплата)
        ▼
Готовый трек ◄── возвращается пользователю
```

Ключевой смысл для владельца: **продукт зависит от нескольких платных внешних сервисов** (в первую очередь Suno AI). Пока оплачены их аккаунты и действуют API-ключи — платформа работает. Полный список — в разделе [3](#3-аккаунты-и-сервисы-для-переоформления).

## 2. Что передаётся

### ✅ Входит в передачу

- **Исходный код** — весь репозиторий (frontend + Edge Functions + миграции БД + тесты).
- **Документация** — 100+ файлов: архитектура, API, деплой, дизайн-система, руководства. Навигация — [`DOCUMENTATION_INDEX.md`](DOCUMENTATION_INDEX.md).
- **База данных** — схема, миграции, RLS-политики (`supabase/migrations/`). Пользовательские данные передаются по отдельному соглашению (см. ниже).
- **Backend-логика** — 135 Edge Functions (`supabase/functions/`).
- **Дизайн-система** — токены, компоненты, брендбук ([`docs/MUSICVERSE_BRAND_KIT.md`](docs/MUSICVERSE_BRAND_KIT.md)).
- **Тесты** — 1810 unit-тестов + 59 E2E-сценариев (Playwright).
- **CI/CD** — GitHub Actions пайплайны (`.github/workflows/`).
- **Конфигурация окружений** — шаблоны (`.env.example`) и полный реестр переменных.

### ⚠️ Требует отдельной договорённости

- **Пользовательские данные** (аккаунты, треки, платежи) — передаются согласно договору и применимому законодательству о персональных данных. Экспорт/миграция БД — по запросу.
- **Активные API-ключи** передающей стороны — **должны быть заменены** ключами заказчика (см. раздел [4](#4-секреты-и-переменные-окружения)). Старые ключи после передачи **отзываются**.

### ❌ Не входит

- Аккаунты и подписки внешних сервисов (заказчик оформляет **свои** — раздел [3](#3-аккаунты-и-сервисы-для-переоформления)).
- Расходы на API (Suno, Klang.io и др.) — тарифицируются напрямую поставщиками.
- Юридические документы конечного продукта (Terms/Privacy для пользователей готовятся заказчиком, черновики есть в `prd/`).

## 4. Секреты и переменные окружения

Полное описание каждой переменной — в [`docs/ENVIRONMENT_VARIABLES.md`](docs/ENVIRONMENT_VARIABLES.md). Шаблон — [`.env.example`](.env.example). Ниже — рабочий реестр для передачи.

### 4.1. Frontend (файл `.env`, префикс `VITE_`)

Эти значения попадают в клиентский бандл — **здесь только публичные ключи**, никаких секретов.

| Переменная                      | Обязательна | Назначение                             |
| ------------------------------- | :---------: | -------------------------------------- |
| `VITE_SUPABASE_URL`             |     ✅      | URL проекта Supabase/Lovable Cloud     |
| `VITE_SUPABASE_PUBLISHABLE_KEY` |     ✅      | Публичный (anon) ключ                  |
| `VITE_SUPABASE_PROJECT_ID`      |     ✅      | Идентификатор проекта                  |
| `VITE_SENTRY_DSN`               |     ⬜      | DSN мониторинга ошибок (рекомендуется) |

### 4.2. Backend (секреты Edge Functions в Supabase → Settings → Edge Functions)

Эти значения **никогда не попадают во frontend** и хранятся только на стороне сервера.

| Переменная                      | Группа   | Назначение                                 |
| ------------------------------- | -------- | ------------------------------------------ |
| `SUPABASE_URL`                  | авто     | Внедряется платформой                      |
| `SUPABASE_ANON_KEY`             | авто     | Внедряется платформой                      |
| `SUPABASE_SERVICE_ROLE_KEY`     | авто     | Внедряется платформой (полный доступ к БД) |
| `SUNO_API_KEY`                  | Suno     | Генерация музыки                           |
| `SUNO_WEBHOOK_SECRET`           | Suno     | Проверка входящих вебхуков Suno            |
| `LOVABLE_API_KEY`               | AI       | Lovable AI Gateway (тексты, анализ)        |
| `KLANGIO_API_KEY`               | MIDI     | Транскрипция Klang.io                      |
| `TELEGRAM_BOT_TOKEN`            | Telegram | Токен бота                                 |
| `TELEGRAM_BOT_USERNAME`         | Telegram | Username бота                              |
| `TELEGRAM_APP_SHORT_NAME`       | Telegram | Короткое имя Mini App                      |
| `TELEGRAM_BOT_MINIAPP_URL`      | Telegram | URL Mini App                               |
| `MINI_APP_URL`                  | Telegram | Публичный URL приложения                   |
| `TELEGRAM_WEBHOOK_SECRET`       | Telegram | Секрет вебхука                             |
| `TELEGRAM_WEBHOOK_SECRET_TOKEN` | Telegram | Токен вебхука (заголовок)                  |
| `TELEGRAM_CHANNEL_USERNAME`     | Telegram | Канал проекта                              |
| `TELEGRAM_NEWS_CHANNEL`         | Telegram | Новостной канал                            |
| `TELEGRAM_SUPPORT_USERNAME`     | Telegram | Контакт поддержки                          |
| `TINKOFF_TERMINAL_KEY`          | Оплата   | Терминал Tinkoff                           |
| `TINKOFF_SECRET_KEY`            | Оплата   | Секрет Tinkoff                             |
| `FAL_API_KEY`                   | Media    | Генерация изображений                      |
| `REPLICATE_API_KEY`             | Media    | AI-анализ                                  |
| `AUDD_API_KEY`                  | Media    | Распознавание аудио                        |
| `CRON_SECRET`                   | Ops      | Защита cron-эндпоинтов                     |
| `ENVIRONMENT`                   | Ops      | `production` / `staging`                   |

### 4.3. Правила безопасности при передаче

- [ ] Все ключи передающей стороны **ротируются** (перевыпускаются заказчиком), старые — **отзываются**.
- [ ] Секреты передаются по защищённому каналу (менеджер паролей / зашифрованное сообщение), **не** в чате и **не** в коде.
- [ ] `SUPABASE_SERVICE_ROLE_KEY` — доступ к БД в обход RLS. Хранить строго ограниченно.
- [ ] После переоформления — проверить, что `.env` заказчика не коммитится (он в `.gitignore`).

## 5. Развёртывание

Подробная инструкция (Vercel / Netlify / Docker / VPS + деплой Supabase) — [`docs/DEPLOYMENT_GUIDE.md`](docs/DEPLOYMENT_GUIDE.md). Релизный чек-лист — [`docs/DEPLOYMENT_CHECKLIST.md`](docs/DEPLOYMENT_CHECKLIST.md).

### Быстрый путь (локальный запуск)

```bash
git clone https://github.com/how2ai-agency/aimusicverse.git
cd aimusicverse
npm install
cp .env.example .env      # заполнить значениями из раздела 4.1
npm run dev               # → http://localhost:8080
```

### Продакшн-сборка

```bash
npm run typecheck         # проверка типов (0 ошибок ожидается)
npm test                  # 1810 unit-тестов
npm run build             # сборка в dist/
npm run preview           # локальный предпросмотр прод-сборки
```

### Backend (Lovable Cloud / Supabase)

```bash
supabase link --project-ref <PROJECT_REF>   # проект заказчика
supabase db push                            # применить миграции
supabase functions deploy                   # задеплоить Edge Functions
```

Требования: **Node.js 22+**, **npm 10+**. Приложение оптимизировано под мобильный Telegram WebView (375×812).

## 6. Эксплуатация и обслуживание

### 6.1. Что смотреть регулярно

| Что            | Где                                                                     | Периодичность  |
| -------------- | ----------------------------------------------------------------------- | -------------- |
| Ошибки runtime | Sentry                                                                  | Ежедневно      |
| Логи backend   | Supabase → Logs / Edge Functions                                        | При инцидентах |
| Баланс Suno AI | Личный кабинет Suno                                                     | Еженедельно    |
| CI/CD          | [GitHub Actions](https://github.com/how2ai-agency/aimusicverse/actions) | При каждом PR  |
| Размер бандла  | `npm run size` (лимит — 950 KB eager)                                   | Перед релизом  |

### 6.2. Бэкапы и восстановление

- **База данных** — включить автоматические бэкапы в Supabase (Settings → Database → Backups). Проверить, что включён Point-in-Time Recovery на прод-тарифе.
- **Хранилище файлов** (аудио) — политика хранения настраивается в Supabase Storage.
- **Код** — GitHub является резервной копией; теги релизов — в разделе Releases.

### 6.3. Типовые операции

| Задача                        | Как                                                                         |
| ----------------------------- | --------------------------------------------------------------------------- |
| Обновить токен бота           | @BotFather → `/token`, затем обновить `TELEGRAM_BOT_TOKEN`                  |
| Сменить URL Mini App          | @BotFather → настройки Mini App + `MINI_APP_URL`/`TELEGRAM_BOT_MINIAPP_URL` |
| Задеплоить одну Edge Function | `supabase functions deploy <имя>`                                           |
| Применить новую миграцию БД   | `supabase db push`                                                          |
| Ротировать API-ключ           | Перевыпустить у поставщика → обновить секрет в Supabase                     |

### 6.4. Поддержание документации

После изменений в коде документация обновляется по регламенту [`MAINTENANCE.md`](MAINTENANCE.md) (чек-лист после каждого спринта, шаблоны, ежемесячная проверка ссылок).
