# Quickstart: Редизайн документации репозитория

**Feature**: 035-repo-docs-revamp
**Date**: 2026-06-29

## Для документатора

Этот гид — для того, кто будет реализовывать редизайн документации. Никаких технических знаний не требуется — только Markdown и понимание структуры проекта.

## Шаг 1: Подготовка скриншотов

1. Запустить приложение локально: `npm run dev`
2. Открыть в браузере (мобильный viewport 375×812)
3. Сделать скриншоты 4 экранов:
   - Главная (`/`)
   - Плеер (открыть любой трек)
   - Студия (`/studio-v2`)
   - Библиотека (`/library`)
4. Конвертировать в WebP (любой онлайн-конвертер)
5. Сохранить в `public/screenshots/`:
   - `home.webp`
   - `player.webp`
   - `studio.webp`
   - `library.webp`

## Шаг 2: Обновление README.md

1. Заменить текущий README на новую структуру (см. `data-model.md`)
2. Добавить шилдсы статуса (скопировать из текущего README)
3. Вставить скриншоты: `![Главная](public/screenshots/home.webp)`
4. Создать секцию «Прогресс проекта» с Mermaid Gantt (данные из ROADMAP.md)
5. Добавить секцию «Для инвесторов» (метрики: звёзды, форки, бандл, спринты)
6. Добавить секцию «Контакты»

## Шаг 3: Ролевая навигация

В `DOCUMENTATION_INDEX.md` заменить текущий каталог на ролевые точки входа:

```
👨‍💻 Я разработчик → CLAUDE.md, ARCHITECTURE_HUB.md, ...
📊 Я инвестор → ROADMAP.md, PROJECT_STATUS.md, ...
```

## Шаг 4: Разделение KNOWLEDGE_BASE.md

1. Прочитать KNOWLEDGE_BASE.md
2. Сопоставить каждую секцию с целевым документом (см. карту в `data-model.md`)
3. Перенести уникальную информацию в целевые документы
4. Удалить дублирующуюся информацию
5. Удалить KNOWLEDGE_BASE.md

## Шаг 5: Единый футер

Добавить футер ко всем корневым .md файлам:

```markdown
---

<div align="center">

[← Предыдущий: FILE.md](./FILE.md) · [↑ К индексу](./DOCUMENTATION_INDEX.md) · [Следующий: FILE.md →](./FILE.md)

<sub>Обновлено: ДД.ММ.ГГГГ</sub>

</div>
```

## Шаг 6: Актуализация MAINTENANCE.md

1. Удалить ссылки на несуществующие файлы
2. Обновить чек-лист обновления документации
3. Добавить секцию по скриншотам
4. Обновить дату

## Шаг 7: Валидация

1. Проверить все ссылки в документации (ручной обход)
2. Открыть README в GitHub — проверить рендеринг шилдсов и Mermaid
3. Пройти путь инвестора: найти ответы на 5 вопросов за 3 минуты
4. Пройти путь разработчика: найти нужные документы за 5 минут
5. Проверить, что все футеры ведут на существующие файлы

## Шаг 8: Коммит и PR

```bash
git add -A
git commit -m "docs: repository documentation redesign (#XXX)"
git push origin 035-repo-docs-revamp
# Создать PR в main
```
